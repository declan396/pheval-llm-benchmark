# Methodology Correction Log

## Summary of Issues Identified

Following feedback from Yasemin Bridges and Jules Jacobsen, two core methodology issues were identified with the initial benchmarking approach:

**Issue 1 — Wrong phenopacket directory passed to PhEval**
The redacted phenopackets (stripped of all gene/disease identifiers) were being passed to PhEval's post-processing step. PhEval requires the original unredacted phenopackets to determine true positives. The redacted versions should only be passed to the LLM.

**Issue 2 — Manual true positive flagging**
Instead of using PhEval's `generate_gene_result` helper, results were being converted manually to parquet format with a `true_positive` column added by hand using a separately built ground truth CSV. This bypassed PhEval's internal true positive identification logic and meant only patients where Claude returned the correct gene contributed to the benchmark — artificially inflating performance metrics.

---

## Fixes Applied

### Step 1 — Add gene interpretations to phenopackets

The original phenopackets generated by `phenotype2phenopacket` only contain a `diseases` field (OMIM ID) with no causal gene information. PhEval's `generate_gene_result` requires an `interpretations` field with a `CAUSATIVE` gene to determine true positives.

Used `p2p add-genes` from the `phenotype2phenopacket` package to inject gene interpretations:

```bash
p2p add-genes \
  -p ~/p2p-work/synthetic_patients \
  -g ~/p2p-work/hpo_resources/genes_to_disease.txt \
  -o ~/p2p-work/synthetic_patients_with_genes
```

Result: 158/200 phenopackets received gene interpretations. The remaining 42 correspond to diseases with no known Mendelian gene in the HPO database and are correctly excluded from gene-level benchmarking.

Example output phenopacket structure:
```json
"interpretations": [
  {
    "diagnosis": {
      "disease": { "id": "OMIM:613286", "label": "Cardiomyopathy, dilated, 1FF" },
      "genomicInterpretations": [
        {
          "interpretationStatus": "CAUSATIVE",
          "gene": { "symbol": "TNNI3" }
        }
      ]
    }
  }
]
```

### Step 2 — Rewrite converter using generate_gene_result

Replaced the manual parquet conversion and true positive flagging with PhEval's `generate_gene_result` helper:

```python
from pheval.post_processing.post_processing import generate_gene_result, SortOrder

generate_gene_result(
    results=df,                        # Polars DataFrame: gene_symbol, gene_identifier, score
    sort_order=SortOrder.DESCENDING,
    output_dir=OUTPUT_DIR,
    result_path=phenopacket_path,      # stem must match phenopacket stem exactly
    phenopacket_dir=PHENOPACKET_DIR,   # synthetic_patients_with_genes/
)
```

PhEval reads the `interpretations` field from the phenopacket and determines true positives internally. No manual flagging required.

### Step 3 — Stem matching via lookup CSV

LLM results are named `patient_001.json` but the gene-annotated phenopackets are named `OMIM_100700_patient_1.json`. PhEval requires exact stem matching between result files and phenopackets.

Used `synthetic_patients_lookup.csv` to map between the two naming conventions:

```
patient_001 → OMIM_100700_patient_1
patient_002 → OMIM_112240_patient_1
...
```

The converter reads this lookup and passes the OMIM-named phenopacket path as `result_path` so stems match.

## Impact on Results

Benchmarking the same Claude + Exomiser (Sonnet) results under both approaches:

| Approach | Top-1 | Top-3 | Top-5 | MRR | n |
|---|---|---|---|---|---|
| Old (manual TP flagging) | 53.8% | 84.6% | 100% | 0.706 | 26 |
| **Correct (generate_gene_result)** | **9.7%** | **15.2%** | **17.0%** | **0.124** | **158** |

The dramatic difference is explained by the change in n: the old approach only counted patients where Claude returned the correct gene in its top 5 (26 patients). The correct approach counts all 158 patients with a known gene — patients where Claude did not return the correct gene score zero and contribute to the denominator. This is the fair comparison.

---

## Key Distinction

- **Redacted phenopackets** (`synthetic_corpus/phenopackets/`) → LLM input only. No disease/gene identifiers.
- **Gene-annotated phenopackets** (`synthetic_patients_with_genes/`) → PhEval post-processing only. Contains causal gene in `interpretations` field.

The LLM never sees the gene-annotated phenopackets. They are used only by PhEval to determine true positives after the fact.
